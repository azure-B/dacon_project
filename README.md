# Dacon 프로젝트 — 함께 일하는 방법

이 문서는 **임현섭님**(화면/front)과 **김정대님**(서버/back)이 Cursor로 작업할 때,
서로 어떻게 소통하면 되는지 정리한 안내서입니다.

웹 개발 경험이 없어도 괜찮습니다. 아래 순서대로만 따라오면 됩니다.

---

## 먼저 알아두기

| 구분 | 담당 | 작업 폴더 | 하는 일 (쉽게 말하면) |
|------|------|-----------|------------------------|
| 화면 | 임현섭님 | `front/` | 사용자가 보는 화면을 만듭니다 |
| 서버 | 김정대님 | `back/` | 화면에 보여줄 데이터를 준비합니다 |
| 문서 | 둘 다 참고 | `md/` | 서로 약속한 내용을 글로 남깁니다 |

**화면**과 **서버**는 따로 만들지만, 실제로는 한 팀처럼 맞물려 돌아갑니다.
그래서 코드만 바꾸는 것보다 **문서를 함께 갱신하는 것**이 더 중요합니다.

---

## Cursor에 프롬프트를 넣으면 어떻게 되나요?

Cursor는 채팅창에 적은 말(프롬프트)을 보고, 프로젝트 안의 코드와 규칙을 읽은 뒤 작업을 진행합니다.

### 임현섭님이 `front/` 작업할 때

1. Cursor 채팅에 하고 싶은 일을 **한국어로** 적습니다.  
   예: *"목록 화면에 검색창을 추가해줘"*
2. Cursor가 `front/` 폴더 안의 파일을 수정합니다.
3. 작업이 끝나면 Cursor가 **`md/jobs/front/`** 에 무엇을 했는지 기록합니다.
4. 화면에서 서버 데이터를 쓰었다면, **어떤 API를 썼는지**도 함께 적습니다.

### 김정대님이 `back/` 작업할 때

1. Cursor 채팅에 하고 싶은 일을 적습니다.  
   예: *"사용자 목록을 내려주는 기능을 만들어줘"*
2. Cursor가 `back/` 폴더 안의 파일을 수정합니다.
3. 작업이 끝나면 **`md/API/README.md`** (API 명세서)를 업데이트합니다.  
   → 임현섭님이 "서버에서 뭘 받을 수 있는지" 바로 볼 수 있습니다.
4. **`md/jobs/back/`** 에도 작업 내역을 남깁니다.

> **팁:** 프롬프트는 구체적일수록 좋습니다.  
> "버튼 추가"보다 **"로그인 화면 오른쪽 위에 로그아웃 버튼 추가"** 가 더 정확한 결과를 줍니다.

---

## API 명세서 — 둘이 소통하는 핵심 문서

**위치:** `md/API/README.md`

이 파일은 **김정대님이 서버에서 제공하는 기능 목록**입니다.  
임현섭님은 화면을 만들 때 **이 문서만 보면** 서버에 무엇을 요청하고, 어떤 형태로 답이 오는지 알 수 있습니다.

### 명세서에 적혀 있는 내용

각 항목마다 대략 이렇게 적혀 있습니다.

| 항목 | 의미 |
|------|------|
| **설명** | 이 기능이 무엇을 하는지 |
| **요청** | 화면에서 서버로 보내는 정보 (없으면 "없음") |
| **응답** | 서버가 돌려주는 정보의 형태 |
| **관련 파일** | 김정대님 쪽에서 수정한 파일 위치 |

### 예시로 이해하기

명세서에 이렇게 적혀 있다고 가정합니다.

```
## GET /api/examples
- 설명: 예시 목록 조회
- 요청: 없음
- 응답: { "success": true, "data": [ ... ] }
```

- **임현섭님:** 화면에 목록을 보여줄 때, 서버의 `/api/examples` 주소로 데이터를 요청하면 됩니다.
- **김정대님:** 목록에 항목을 하나 더 넣거나 형식을 바꾸면, **반드시 이 문서도 같이 수정**해 주세요.

### 꼭 지켜야 할 순서

```
김정대님이 서버 기능 추가/변경
        ↓
md/API/README.md 업데이트
        ↓
임현섭님이 명세서 보고 화면 연결
        ↓
md/jobs/front/ 에 "어떤 API를 썼는지" 기록
```

**서버를 먼저 만들고, 명세서를 갱신한 뒤, 화면을 연결**하는 순서가 가장 덜 헷갈립니다.

---

## 작업 내역(jobs) — 서로 뭐 했는지 확인하는 곳

| 폴더 | 누가 쓰나요 | 내용 |
|------|-------------|------|
| `md/jobs/back/` | 김정대님 | 서버에서 무엇을 만들거나 고쳤는지 |
| `md/jobs/front/` | 임현섭님 | 화면에서 무엇을 만들거나 고쳤는지, **쓴 API 주소** |

카카오톡으로 "나 어제 그거 했어" 대신, **여기에 남겨 두면** 나중에 찾기 쉽습니다.

### 파일 이름 규칙

- 큰 작업: `2026-09-01_로그인화면.md` (날짜_한줄요약)
- 작은 수정: `2026-09-01.md` 안에 시간과 함께 짧게 추가

---

## 폴더 구조가 궁금할 때

**`md/folder.md`** 에 프로젝트 전체 폴더 설명이 있습니다.  
새 폴더를 만들거나 구조가 바뀌면 이 파일도 함께 고칩니다.

---

## 자주 쓰는 실행 방법

서버와 화면은 **둘 다 켜야** 화면에서 데이터를 볼 수 있습니다.

```bash
# 터미널 1 — 김정대님 (서버, 포트 5000)
cd back
npm run dev

# 터미널 2 — 임현섭님 (화면, 포트 3000)
cd front
npm run dev
```

브라우저에서 `http://localhost:3000` 을 열면 화면을 볼 수 있습니다.

## 한눈에 보는 협업 흐름

```
┌─────────────────┐         ┌─────────────────┐
│   김정대님       │         │   임현섭님       │
│   back/         │         │   front/        │
│   서버 코드 작성 │         │   화면 코드 작성 │
└────────┬────────┘         └────────┬────────┘
         │                           │
         ▼                           ▼
  md/API/README.md            md/jobs/front/
  (기능 설명서 작성)           (쓴 API + 변경 파일)
         │                           │
         └───────────┬───────────────┘
                     ▼
              md/jobs/back/
              (서버 변경 내역)
```

## 헷갈릴 때 체크리스트

### 김정대님 — 작업 끝나기 전

- [ ] `back/` 코드 수정 완료
- [ ] `md/API/README.md` 에 새 기능/변경 사항 반영
- [ ] `md/jobs/back/` 에 작업 내역 기록

### 임현섭님 — 작업 끝나기 전

- [ ] `md/API/README.md` 에 필요한 기능이 있는지 확인
- [ ] `front/` 화면 연결 완료
- [ ] `md/jobs/front/` 에 **사용한 API 주소**와 **수정한 파일** 기록

---

## 더 자세한 규칙이 필요할 때

Cursor가 자동으로 읽는 규칙은 `.cursor/rules/` 와 `AGENTS.md` 에 있습니다.  
일상적으로는 **이 README와 API 명세서만** 잘 맞춰도 충분합니다.

궁금한 점이 있으면 서로 `md/jobs/` 와 `md/API/README.md` 를 먼저 확인한 뒤 물어보세요.
